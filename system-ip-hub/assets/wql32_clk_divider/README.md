# 时钟分频器

## 当前结论

偶数分频分支的设计思路可用，但需要满足严格参数约束并完成时钟实现检查；奇数分频分支存在多驱动和组合自反馈问题，当前版本不可直接综合使用。

## 设计意图

模块试图根据 `DIV_FACTOR` 和 `DIV_MODE` 生成输入时钟的整数分频时钟：

- 偶数分频：计数到半周期后翻转输出。
- 奇数分频：分别在输入时钟不同边沿生成半周期波形，再组合得到近似 50% 占空比输出。
- `clk_en`：允许或暂停分频计数。

## 参数与约束

| 参数 | 含义 | 当前约束 |
| --- | --- | --- |
| `DIV_FACTOR` | 分频系数 | 偶数模式下应为大于等于 2 的偶数 |
| `DIV_MODE` | 偶数/奇数模式选择 | 奇数模式当前不可用 |

偶数模式中，输出每经过 `DIV_FACTOR/2` 个输入时钟边沿翻转一次，因此完整周期为 `DIV_FACTOR` 个输入周期。`clk_en` 拉低后输出保持当前电平，而不是强制回到低电平。

## 已知问题

- 奇数分频逻辑对 `clk_out` 存在多个过程赋值。
- 奇数分频的组合逻辑包含类似 `clk_out = clk_out | clk_half` 的自反馈，可能形成组合环路或仿真不收敛。
- 条件 generate 的写法依赖 SystemVerilog 编译模式，严格 Verilog 工具可能不接受。
- 参数未对非法值进行保护；`DIV_FACTOR` 过小会导致计数器宽度或终值异常。
- 生成的新时钟会引入新的 clock domain，必须补充 generated clock、时钟树和 STA 约束。

## 推荐用法

优先使用工艺库时钟分频单元、PLL/MMCM、全局时钟资源或 clock-enable 架构。若确实要使用 RTL 分频时钟，建议只保留并重写偶数分频分支，同时由后端确认时钟树实现方式。奇数分频应整体重构，不能在当前实现上直接启用。

## 建议验证项

1. 对合法偶数分频系数检查周期、占空比和启停行为。
2. 在计数临界点切换 `clk_en`，检查是否出现窄脉冲。
3. 检查复位释放后的第一个输出边沿。
4. 执行 lint、综合和组合环路检查。
5. 为输出时钟建立 generated-clock 约束并执行 CDC/STA 分析。
