# FF CAM

## 当前结论

该模块意图清晰，但当前源码同时存在写使能错误、依赖模块名称不一致和组合锁存风险，不能直接使用。

## 设计意图

`ff_cam` 使用触发器阵列实现小容量 CAM（Content Addressable Memory）。每个表项由有效位和数据组成，支持：

- 按地址写入表项。
- 按地址读取或清除表项。
- 输入搜索 key，与所有有效表项并行比较。
- 将匹配 bitmap 编码为命中地址。
- 通过 `FLOP_IN/FLOP_OUT` 控制输入、输出寄存级。

## 搜索语义

理想情况下，匹配位应满足：

```text
match[i] = entry_valid[i] && (entry_data[i] == search_key)
```

当前接口没有独立的“命中有效”输出，也没有定义多项同时匹配时的优先级，因此即使修复编译和控制问题，调用者也无法可靠区分“未命中”和“命中地址 0”。

## 已知问题

- 写地址译码 `wen_bitmap` 错误地受读使能 `ren` 控制，而不是写使能 `wen`，导致正常写操作可能失效。
- 源码实例化 `idh_onehot2bin`，与资产中的编码器模块名称不一致，可能无法展开设计。
- 组合逻辑中的 `o_saddr` 在 `sen=0` 时未完整赋值，会推导锁存器。
- 缺少 `o_match_valid` 或等价信号。
- 未定义重复 key 导致多匹配时的行为；结果取决于编码器实现。
- 清除、写入和搜索同一表项发生在同一周期时，优先级和可见性未明确。

## 修复建议

1. 将写译码的门控改为 `wen`，并明确写、清除的优先级。
2. 使用经过验证的 priority encoder，同时输出 `match_valid` 和可选的 `multi_match`。
3. 为全部组合输出设置默认值，消除锁存器。
4. 明确是否允许重复 key；若不允许，可增加 duplicate 检测。
5. 明确定义同周期写/清除/搜索的数据可见性。

## 建议验证项

- 空 CAM 搜索、单项命中、地址 0 命中和末地址命中。
- 无命中及多个重复项同时命中。
- 写、读、清除、搜索的随机交叉操作。
- `FLOP_IN/FLOP_OUT` 不同组合下的接口延迟。
- lint、锁存、多驱动和未解析实例检查。
