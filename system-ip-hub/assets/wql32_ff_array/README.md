# FF Array

## 当前结论

当前源码存在端口缺失和 generate 结构错误，无法直接编译。该文件应视为“设计草稿”，不应直接集成到工程。

## 设计意图

模块希望用触发器阵列实现一个单写、单读的小容量存储体，并通过参数控制输入和输出是否额外寄存。写地址被译码为 one-hot 写使能；读取时对各项数据进行选择并输出。

这类结构适合深度较小、需要异步读或希望由综合工具实现为寄存器阵列的场景，不适合替代大容量 SRAM。

## 预期参数

| 参数 | 含义 |
| --- | --- |
| `DATA_WIDTH` | 每项数据位宽 |
| `DEPTH` | 存储项数量 |
| `ADDR_WIDTH` | 地址位宽，通常为 `$clog2(DEPTH)` |
| `FLOP_IN` | 是否寄存输入控制和数据 |
| `FLOP_OUT` | 是否寄存读数据输出 |
| `END_OF_LIST` | 源码中声明但未形成清晰有效的功能 |

## 已知问题

- RTL 内部使用了 `i_ren`，但模块端口中没有声明该输入。
- 输入寄存选择部分存在重复或不匹配的 `generate/else` 结构，语法不成立。
- `ren`、`raddr` 等内部信号的赋值关系不完整，修复语法后仍需检查是否出现多驱动。
- `END_OF_LIST` 参数未形成明确的存储边界语义。
- 未定义非法地址、同时读写同一地址以及复位后未写存储项的行为。

## 修复建议

1. 明确定义端口：写使能、写地址、写数据、读使能、读地址和读数据。
2. 将 `FLOP_IN`、`FLOP_OUT` 分别整理为互斥且完整的 generate 分支。
3. 明确同址读写策略：read-first、write-first 或 no-change。
4. 对非 2 的幂深度增加地址越界处理。
5. 若不要求清零数据阵列，复位只清有效位或输出寄存器，避免产生大规模复位网络。

## 建议验证项

- 编译、lint 和多驱动检查。
- 每个地址的单次写读及连续写读。
- 同址同时读写的确定性行为。
- 首地址、末地址和非法地址。
- `FLOP_IN/FLOP_OUT` 四种参数组合下的延迟一致性。
