# One-Hot to Binary Encoder

## 当前结论

当前源码存在参数、函数和 generate 名称不一致等多处结构性错误，无法直接编译。建议保留需求定义，但重新实现编码器。

## 设计意图

模块希望把 one-hot bitmap 转换为对应的二进制索引，并尝试通过分层或树形结构降低大位宽编码的组合延迟。

预期语义应明确为：

- 输入仅有一个 bit 为 1：输出该 bit 的索引。
- 输入全 0：需要 valid 输出指示无有效索引。
- 输入 multi-hot：需要定义优先级或报告非法输入。

## 已知问题

- `BITMAP_CELL` 与 `BITMAP_CEIL` 等参数名混用。
- 函数名存在 `bimap_*` 和 `bitmap_*` 拼写不一致，调用无法解析。
- generate 分支和函数赋值关系不完整，可能产生未驱动或重复驱动。
- 未提供独立 valid 输出，导致全 0 输入与 bit 0 命中无法区分。
- 未定义 multi-hot 输入的优先方向和结果。
- 对位宽为 1、非 2 的幂位宽及尾部不足一个 cell 的处理不清晰。

## 推荐重构方式

小位宽场景建议采用简单、可读的优先编码循环，并同时输出：

- `o_valid`：输入至少有一个 bit 为 1。
- `o_index`：选中 bit 的索引。
- 可选 `o_multi_match`：输入不是 one-hot0。

高频大位宽场景可使用分层 priority encoder，但每一级应有明确的 valid/index 结构，并对尾部补零。若输入协议保证严格 one-hot，也应在仿真或形式验证中增加 `$onehot0` 断言。

## 建议验证项

1. 全 0、bit 0、最高 bit 和每个单 bit 遍历。
2. 随机 multi-hot 输入，按定义检查最低或最高优先级。
3. 位宽 1、2、非 2 的幂及大位宽参数。
4. 与软件参考模型逐向量比对。
5. 编译、lint、未驱动、越界和组合环路检查。
