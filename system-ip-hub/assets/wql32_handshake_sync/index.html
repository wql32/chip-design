功能与接口

模块通过两级 req/ack 同步链，把一组稳定保持的数据从源域传到目的域，适用于低频配置或控制数据。

  • 源域只在源时钟上升沿且 src_vld && src_ready 时接受一项数据。
  • src_ready = src_rst_n && !req && !ack_sync，必须等待 req 和返回 ack 全部撤销，才能接受下一项。
  • 源端可持续拉高 valid，但在未被接受时必须保持当前待发送数据。
  • 目的域没有 ready，消费者必须在 dst_vld=1 的目的时钟上升沿接受 dst_data。
  • dst_vld 与 dst_data 同拍寄存，valid 仅保持一个目的时钟周期；无 valid 时数据保持上一次结果。

握手与数据稳定性

  1. 源域接受数据，锁存 data_reg 并拉高 req。
  2. req 经目的域两级同步，再与其独立延迟值比较检测上升沿。
  3. 目的域同时寄存数据和 valid，并拉高 ack。
  4. ack 经源域两级同步后，源域撤销 req。
  5. 目的域看到同步后的 req 撤销，随后撤销 ack。
  6. 源域看到同步后的 ack 撤销，重新开放 ready。

功能逻辑只读取同步链第二级；第一级不参与事件沿检测。同步链标记了 ASYNC_REG，但属性不能替代实现检查。数据总线为 MCP 结构，在整次握手期间保持稳定。

参数与复位约束

  • DATA_WIDTH >= 1。
  • 两个域异步置位复位，各自必须同步释放；释放同步由集成端保证。
  • 运行中复位必须协调两个域，并停止发起新请求；复位丢弃在途事务。
  • 不保证单边复位时的 exactly-once 或自动恢复；系统需要协调清空与重发。
  • 必须为同步链和稳定数据总线建立对应 CDC/MCP 时序约束。
  • 吞吐受完整 req/ack 往返限制，连续高速数据应使用异步 FIFO。

本次修复

  • 将错误的 req_sync_1 && !req_sync_0 改为第二级同步值与独立延迟值的上升沿检测。
  • ready 增加返回 ack 已撤销条件，避免握手尚未结束就覆盖源端数据。
  • 注册目的端 valid，使消费者看到的 valid 与对应数据一致。
  • 保持现有端口、低有效异步复位和单项在途结构。

验证记录

  • pyslang 12.0.0：实际 RTL 与 tb_handshake.sv 的 4 组时钟参数展开，未发现编译错误。
  • Python 周期模型：5 组时钟比／相位（含同时边沿）、连续请求及 34 个协调复位切入点；以事务队列检查顺序、唯一性和有界完成。
  • Icarus Verilog/vvp 已实际执行自检 SystemVerilog testbench，4 组时钟配置全部通过。
  • 模型不模拟亚稳态，以上结果不代表 CDC 或 STA 签核。
