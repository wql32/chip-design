# 双写单读 FIFO

## 当前结论

该文件表达了“每周期最多写入两项、读取一项”的 FIFO 结构，但当前源码存在语法和边界控制问题，**不能直接编译或集成**。建议将它作为双写 FIFO 的设计草稿，修复后再复用。

## 预期功能

- `i_we_0/i_wdata_0`：写端口 0。
- `i_we_1/i_wdata_1`：写端口 1。
- 两个写端口同周期有效时，端口 0 写当前写指针，端口 1 写下一地址。
- `i_re`：读取一项，`o_rdata` 为当前读指针指向的组合读数据。
- `o_full/o_afull/o_empty`：容量状态。
- `o_overflow/o_underflow`：非法写入和读取指示。

## 参数

- `FIFO_WIDTH`：每项数据宽度。
- `FIFO_DEPTH`：存储深度。
- `AFULL_DEPTH`：almost-full 阈值。
- `FIFO_NAME`：预留的日志名称，当前 RTL 未使用。

## 已知问题

1. 模块名 `2wlr_fifo` 以数字开头，不是合法的普通 Verilog 标识符。
2. `fifo_cnt_delta` 使用圆括号表示拼接，语法应为花括号拼接。
3. 读写指针依据原始 enable 推进，没有使用 full/empty 条件进行保护。
4. 满状态继续写或空状态继续读时，计数器和指针仍会变化，overflow/underflow 只是告警，不能保护状态。
5. 双写时没有检查剩余空间是否至少为 2，剩余一个 entry 时可能越界写入。
6. 指针依赖自然回绕，实际使用要求 `FIFO_DEPTH` 为 2 的幂。

## 修复建议

将写入数计算为 0/1/2，并根据可用空间生成实际 `write_accept_count`；读指针、写指针和计数器只能由真实接受的读写事件推进。双写边界需要单独覆盖“剩余 0、1、2 个 entry”三种情况。
