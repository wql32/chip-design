# 空闲指针管理器

## 当前结论

2026-10-21 修复指针 0 漏分配、无效分配推进、总空闲计数错误及重复释放造成的重复分配。状态 **Constrained**，实际 RTL 仿真通过。

## 接口契约

PTR_NUM >= 1，PTR_WIDTH >= max(1, ceil(log2(PTR_NUM)))。合法指针 0 到 PTR_NUM-1，END_OF_LIST 未使用。低有效同步复位归还全部指针、清空两项预取缓存。

- 仅在上升沿 i_alc_req && o_alc_vld 时分配 o_alc_ptr。
- 无有效项时请求忽略、输出指针为零；调用者不能仅凭 req 推进。
- **o_ptr_num 表示全部空闲数（bitmap + 缓存），不是缓存有效项数。** 原依赖缓存计数的集成需调整。

## 架构与状态不变量

空闲 bitmap → 最低位置优先选择 → 两项预取缓存 → 分配；allocated bitmap 标记真正交给调用者的指针。每个指针恰属于 bitmap、缓存、已分配之一。预取不改变总空闲数，真实分配减一，合法释放加一。缓存满且当拍真实分配时允许补充。

复位后首项需先预取；因此总空闲数非零不保证 o_alc_vld=1。耗尽后释放的指针也要经过预取，不能同拍直通。

## 释放与并发边界

- 仅接受边沿前已经分配的合法指针释放。
- 重复、越界以及释放仍在缓存/bitmap 内的指针均忽略。
- 本拍刚分配的指针不能同拍释放，应在后续周期释放。
- 不同指针可同拍分配、释放，总空闲数不变。
- 无 release-ready/错误输出，调用者仍应监控非法释放，忽略策略不是错误报告。
- 最低位置优先不承诺轮询公平性；大池优先路径需综合时序评估。

## 验证记录

Icarus Verilog 执行 tb/tb_pointer_pool.sv，PTR_NUM=1/2/3/9/64/384，共 6 组。耗尽并确认含指针 0 的每项只分配一次，覆盖满空缓存、合法/重复/越界释放、无效分配、并发和复位。每组 3,000 次随机事务，独立 allocated 集合和空闲总数核对。pyslang 12.0.0 展开通过。

未执行 formal、综合、面积或 STA。
