# RTL 修复与验证记录 · 2026-10-21

## 修复范围

本批仅修改公开资产目录 assets/wql32_rtl 下六个模块及其文档、元数据、自检测试；不修改公司 RTL，也不改历史 mx_rtl 原始副本。

| 模块 | 修复与集成约定 |
| --- | --- |
| basic_fifo | 真实读写保护，任意正整数深度回绕，满且读可接受写，空读不旁路 |
| 2w1r_fifo | 批次全部接受或全部拒绝，端口 0 在前，端口 1 独写不留空洞 |
| ff_array | 输入字段完整流水，消除多驱动，输出寄存与组合模式明确定义 |
| ff_cam | 写不依赖读使能，有效位搜索，重复 key 最低地址优先，同 entry 写优先清除 |
| free_ptr_mng | 包含指针 0，仅真实分配更新，非法/重复释放保护，两项预取，总空闲数包含缓存 |
| clk_divider | 奇数模式正负沿独立寄存，消除自引用与多驱动；完成最后一个已使能半周期后暂停 |

端口名、顺序和数据位宽参数保留；深度 1 的默认地址位宽改为最小 1。clk_divider 输出由内部寄存驱动的 wire 对外输出。指针池 o_ptr_num 从原缓存项数更正为总空闲数，属于必须复核的集成语义。

## 已实际执行

项目根运行：

```powershell
python -m unittest discover -s tests -v
```

19 项 unittest 测试通过，无 skipped。包括两批 RTL 的 53 组 pyslang 参数展开及 Icarus Verilog/vvp 自检仿真配置，另有独立 Python 模型与站点测试。

仿真执行实际 .v 源码，并以队列、存储数组、已分配集合或边沿计数参考值逐项断言；不是仅执行 Python 行为模型。工具为 pyslang 12.0.0、Icarus Verilog 12.0(devel)，项目内工具目录不参与导出。

初次运行存储组合输出及奇数分频测试发现初始化 X：测试平台仅将复位声明为初始 0，未产生真实复位事件。改为在首个时钟边沿前产生 1→0 跳变；同时将中途异步复位避开采样边沿，消除测试平台调度竞态。未通过放宽断言掩盖失败。

本批仿真数据宽度为 16；未穷举全部参数、随机种子或所有输入序列。

## 状态与未覆盖项

- 六项状态由 needs_fix 更新为 constrained，而不是 ready。此前四项也补充了实际动态仿真通过记录，没有重复修改其 RTL。
- 双写 FIFO 的旧手工验证状态保存在 metadata 的 verification_history，不继承旧版 formal/综合/性能结果。
- CAM 原接口无 hit-valid，无匹配与地址 0 命中仍不可区分。
- FF array 阵列不复位，未初始化内容不保证；寄存读写冲突取旧值，组合读写后反映新值。
- 指针池非法释放静默忽略，没有错误响应；首项和回收项需要预取延迟，不保证最低位置优先的公平性。
- 分频器不是工艺级无毛刺单元；复位可截短脉冲。尚需 generated-clock、半周期路径、最小脉宽、CTS 与 STA。
- 未执行专门 lint、formal、综合、CDC/RDC 或时序/面积/功耗签核；数字仿真不模拟亚稳态和真实门延时。

详细时序与边界见各模块 README，测试平台位于对应资产 tb 目录，可随静态站点一起浏览和下载。
