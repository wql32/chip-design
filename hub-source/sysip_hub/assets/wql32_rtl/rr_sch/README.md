# Round-Robin Scheduler

## 当前结论

2026-10-21 已修复请求前缀掩码、masked request 有效判断，以及暂停时 grant 仍有效的问题。当前状态为 **Constrained**：实际 RTL 参数展开、算法模型及 Icarus 动态仿真通过；未进行综合检查。

## 接口与服务语义

- `i_req[N-1:0]`：候选请求，低索引先开始轮询。
- `i_sch_en=1`：本周期允许且接受一次服务；若存在请求，本周期 grant 在上升沿被消费，轮询状态随后推进。
- `i_sch_en=0`：不接受服务，grant 和 valid 为零，轮询状态保持。
- `o_gnt`：one-hot0 授权向量，必须是当前请求的子集。
- 为保持现有接口，`o_gnt_vld` 仍为 N 位；**只有 bit 0 表示标量 valid，其余位为 0**，它不是逐端口有效 bitmap。
- `i_rst_n` 为低有效同步复位；复位期间输出门控为零，复位上升沿重置轮询位置。

这里的 enable 是服务接受条件。该模块没有独立 ready、pending grant 或事务锁定状态；暂停期间不保持一个有效 grant，不能直接当作完整的 ready/valid 输出级。

## 算法与状态不变量

1. 先从上次授权位置之后的请求中选择最低有效 bit。
2. 若该范围没有请求，回绕到完整请求向量中选择最低有效 bit。
3. 仅在 `i_rst_n && i_sch_en && |i_req` 时推进状态。
4. 状态掩码只保留本次授权位置之上的 bit。
5. 无请求或暂停时状态保持；持续全请求时按 0、1、…、N-1 循环。

## 参数与使用约束

- `REQ_NUM >= 1`，支持非 2 的幂端口数。
- enable 拉高时，下游必须能够接受本周期选中的请求。
- 请求及相关 payload 必须满足采样边沿的建立／保持要求。
- 若需要保持授权直到独立 ready 到达，应在外部增加 pending/锁定逻辑，或使用对应的仲裁接口。
- 大端口数下，前缀 OR 和选择路径需要根据目标频率进行综合与时序评估。

## 本次修复

- 前缀条件只包含当前 bit 以下的请求，避免请求把自身屏蔽。
- 将 `masked_req == 1'b1` 改为归约 OR，覆盖所有有效请求位置。
- grant 和 valid 统一由 reset、enable 与真实请求门控。
- 保留旧端口宽度，并明确向量 valid 的兼容语义。
